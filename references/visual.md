# 图文与封面标准

## 固定视觉识别

沿用账号现有橙色章节、米白底、深色正文、小段落。正文建议 16px、约 1.8 行距；按手机实际显示调整。原始 Markdown 保留方便编辑，不把全文转图片。

封面首选“真实界面/成果截图 + 简短任务标题 + AI顺手工具箱标识”，结构稳定、素材随文章变。可参考 [cover-layout.svg](../assets/cover-layout.svg) 的版式；该文件是模板，不是实测截图。

封面主画幅按 2.35:1 准备，同时检查 1:1 分享裁切。标题与关键对象尽量靠中心安全区域；必须实看手机预览，不只验证文件尺寸。

需要制作图或核查裁切时，按 [图与封面制作](visual-production.md) 执行。`scripts/preview_cover.py` 提供完整横图、中心方形、安全区和缩略图的离线预览；它不识别文字，也不替代微信手机预览。

## 正文重点突出

先决定读者扫读时应该看到什么，再选写法。优先突出本篇成果、编辑判断、关键动作、验收标准，以及会影响能否开始的费用、权限或数据前提。不是所有工具名、数字和新名词都要强调。

| 内容作用 | 优先写法 | 选择条件 |
|---|---|---|
| 核心结论或最关键动作 | 段内短语用 `**加粗**`，必要时结论独立成段 | 保留上下文，不把整段变粗 |
| 操作前提、容易漏掉的限制 | 带“操作前确认”“注意”等标签的 `>` 提示块 | 只在会影响下一步的地方使用，不每节放卡片 |
| 执行顺序或验收项 | 短小标题、有序步骤或清单；关键动作适度加粗 | 编号对应真实顺序，清单项能执行或检查 |
| 可复制提示词、模板字段 | 纯文字代码块或清楚分隔的文字区，说明放在块外 | 块内不添加仅为高亮的 `**`、HTML 或装饰字符 |
| 选择工具或结果差异 | 简短对照表、并列清单或前后对照 | 手机宽度能容纳；信息多时拆成短项 |

例如：

```markdown
要整理的成果是包含**任务、责任人、截止日期、待确认事项**四列的待办表。没有来源依据的字段，保留为待确认。

> **操作前确认：**先用不敏感的示例记录练习，再确认所用模型服务的数据去向。

完成后检查：**每项待办都能在原记录中找到依据**。
```

每篇通常有清晰可见的重点，但不规定数量、比例、位置或固定组合。段内加粗选短语或短句，避免整段、连续多段、所有列表项都加粗。若拿掉普通文字后重点仍是一大段，收窄强调范围。只有普通叙述的段落可以不强调。

强调不能改变事实含义：不能只高亮“免费”而把调用费用藏在后面，也不能突出效果而弱化必要条件。推荐与条件放在读者容易同时看到的位置。避免反复叠加加粗、颜色、下划线、emoji 和大字号，颜色不能成为理解重点的唯一线索。

保持账号已有橙色与浅底提示风格。当前连接的本地渲染链路支持 Markdown 加粗、引用块、列表和代码块；引用块有浅底与橙色侧边线。未确认支持 `==高亮==`、`<mark>` 或任意内联 HTML 背景色，不在源稿中默认使用，也不承诺会显示成黄色高亮。以后若换成支持背景高亮的真实排版能力，再少量用于关键短语，仍保留语义和可复制文本。

局部改稿只调整受影响内容，不为凑重点重排全文。与近期文章比较时，变化强调位置和组织方式，不能把“结论卡—步骤卡—提醒卡”变成每篇的新固定模板。

## 现有连接能力

当前 create_draft/update_draft 接口只接收 title、markdown、source_urls 和请求字段，没有 cover 参数。服务会自动生成米白橙色的标题封面；不能在工具调用中编造 cover 字段，也不能宣称已经换成截图封面。

可接受时使用服务自动封面，并记录“标题封面”。用户要求截图封面时，先交付本地封面/模板；通过用户本人后台更换或另行获得授权的真实可用接口处理。新增截图封面能力是独立的服务改动，不默默修改云端部署。

cover_path 只证明记录了文件位置；cover_media_id 为空也不足以证明微信封面为空。要核实 live draft 的 thumb_media_id/封面预览；现有 read_draft 未暴露封面字段时只报告核实能力限制。

## 正文图片

按解释作用安排：成果图说明能做成什么；步骤图解决入口和操作位置；对照图帮助判断差别；验收图说明做到哪一步才算完成。没有解释作用的官方宣传图可省略，不设图片数量和字数配额。无需展示操作或结果差异的短提示词、短清单可以少图或无图；不能把这条例外用来省略长教程的图文策划。

- 官方图标为“官方示例”，写清版本和展示的功能；不能用旧界面图证明新增功能已实测。
- 真正的步骤截图由实际运行产生，遮住敏感信息。拍不到就标待补，不生成看似真实的界面图。
- 提示词和主要操作文字留在正文，读者可复制；图片提供位置、结果或对照。
- 配图紧跟对应步骤，附来源或“本次实测截图”及版本；后者需证据。
- 缺少可靠图片时保留内容并报告缺口；版权未确认的官方照片不强行转载。

内容标准与传输条件分开判断。当前服务源码核对日期为 2026-10-11：正文最多 15 张公开 HTTPS 图片，每张不超过 1,000,000 字节，实际 MIME 及文件签名须为 PNG/JPEG。没有“至少两张”或“仅官方图”的底层限制；工具提示中的数量建议不作为凑图门槛。以后以实际 schema 与服务约束为准。

URL 后缀不能证明格式：无扩展名的官方项目卡片可能是有效 PNG，`.png` 也可能返回 HTML。提交前加 `--verify-media` 验证实际响应，不凭 ledger 自述的 mime/bytes 宣布已通过。图片解码、清晰度、版权与手机显示另行检查。

自有截图、原创示意图和许可明确的图片可以使用，记录来源、敏感信息处理和用途。生成的示意图标为示意，不冒充真实界面。当前接口不能直接上传电脑上的路径；有合适且已获授权的公开托管入口才可转为 HTTPS，不默认公开用户图片或资料。无法传输时保留本地图与缺口说明，或在不影响理解时删去图位，不添加无关图片。

超限图片可以在保留原图的情况下制作符合限制的副本；使用真实可用且已授权的上传入口，或选择有解释价值的较小官方图。不能宣称本地压缩后已被当前接口读取。

## 图文策划与成稿检查

写作前按任务安排必要图位，记录每图的位置、要回答的问题、素材来源和取法。数量由需要决定；某个例子适合三张图，不意味着以后篇篇三张。

能看出成果差异时，尽早放成果图或原始输入与结果的对照，让读者知道后文要做成什么。步骤图只截与动作有关的区域，标出入口与结果；引用核对、导出或可编辑性等验收环节可用截图或清楚的示意图说明。

没有产品实测截图时，使用本篇材料制作成果示意、流程图或原文对照，标“编辑示例”“流程示意”“非软件截图”；不画看似真实的软件窗口、按钮、账号或工具输出。生成示意图不证明产品已跑通，截图无法取得也不意味着全文只能用文字。

关键输入、提示词和模板仍提供可复制文字。长提示词有明确的开始标签和分条说明，字号与对比度以手机可读为准；不能把它做成只可看的图片。本地 CSS 调整、连接渲染与微信显示分别核验，不能把本地样式当作微信已生效。

导出预览后检查实际图片节点和文件：图片不是只留在素材目录，图注与正文位置吻合，文件能打开且没有裁掉关键文字。封面可以在预览的独立审核区域展示；正文首屏按需要展示成果图，封面文件存在不代表正文已配图。

纯文字的长操作稿需编辑判断：读者是否看得到成果、找得到入口、核对得了结果？零配图预检是提醒，不是数量门槛。若仍无图，在内部 `visual_reason` 中解释为什么文字足够，不能仅写“没有截图”。

## 手机检查

先扫读标题、加粗文字和提示块，看能否快速找到成果、关键动作、验收与必要前提；再检查是否强调过密、条件被弱化、提示词混入装饰标记。检查封面裁切、标题文字、长代码换行、表格横向溢出、图片清晰度、编号与资料区。后台/API 保存成功和手机显示正常分别记录；本地 HTML 正确不等于微信手机预览已通过。
