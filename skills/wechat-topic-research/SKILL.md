# 公众号选题研究

为总入口 [ai-toolbox-wechat](../ai-toolbox-wechat/SKILL.md) 提供可写、有依据且不重复的选题。总入口负责成稿、审稿与反馈；用户已指定工具或问题时，围绕它寻找合适任务，不重新扩成全网选题。

## 伴随依赖与共享规范

本 Skill 与 `ai-toolbox-wechat` 必须安装为同级目录。开始先读 [统一台账与核验口径](../ai-toolbox-wechat/references/workflow.md)；按任务再读 [编辑标准](../ai-toolbox-wechat/references/editorial.md) 与 [交接约定](../ai-toolbox-wechat/references/collaboration.md)。这些文件是共享规范的单一来源，不在本目录复制。

总入口或必需参考缺失时，说明缺少哪些文件；可以在当前请求范围内完成独立资料核对，但不能声称已按账号台账查重或完成统一交接。已有阅读版不赋予工具连接或私有台账权限。

## 研究与筛选

1. 通过 `list_workflow_entries` 分页查询同一云台账、已有文章与本批候选，按“工具官方标识＋读者具体任务”比较 `article_key`。同时比较已发表、草稿中、待研究与已否决记录；不能仅靠标题不同认定新题。只读任务不写台账，未覆盖的历史明确记录范围。
2. 用 X、GitHub 或其他渠道发现线索，再回到官方 README、文档、版本记录、许可及下载入口核查。记录来源链接和核查日期；帖子推荐量、星数是发现信号，不能证明使用人数、效果或“最好用”。检索使用当前可用且已获授权的能力，不新增登录、依赖、模型调用或付费服务。
3. 说明读者任务、现有做法、改善哪一步、设置/学习/费用成本与证据缺口，给出“写、收窄、待验证或放弃”的理由。系统、硬件、账号、代码能力和数据去向会改变适用人群时，放在建议之前。按 [内容方法与辅助路由](../ai-toolbox-wechat/references/content-craft.md) 检查任务是否具体、证据是否足够、对该读者是否值得使用；标题中的用途与结果必须能由正文及实际成果兑现，不用固定营销钩子、争议或流量预测替代判断。
4. 提供可支撑的写作方向与一个具体示例构想，选用现有 `writing_mode`；官方文档、源码检查和实测分别标明。没有操作记录不建议写成实测教程，不编造效果数字、亲测口吻或截图。

## 交接

沿用现有 `packet.json` 与字段，不创建第二套题卡 schema。将研究放入 `topic_brief`、`source_urls`、`evidence_level` 和 `editorial_note`，以稳定 `article_key` 对应私有台账；标题角度、建议示例和缺图记录用现有编辑字段。多个候选可以用表格供用户选择，进入写作的候选再补齐交接包。

获授权记录选题时，按共享流程先读云台账 revision，再以 patch 保存 `topic_record`；只读研究不写。研究结论与“已成稿、已审稿、已存微信”分别汇报。研究阶段不生成草稿投递请求，不调用创建、更新或发表；需要继续写作时交回总入口，已明确要求完整成品的任务继续完成后续已授权环节。


## v2.0.0 视觉证据与产量取舍

沿用evidence_level、visual_plan、visual_reason与editorial_note，不另加一套强制分级字段：有真实成果或官方演示时围绕可见结果写短图文；只有可靠文档但缺产品图时可做准确的文档示意，图内标“依据官方资料整理、非软件截图”；只有宣传描述或无法核实核心功能时收窄成短评/候选，不自动批量成稿。资料和视觉证据达不到标准时，宁可少于计划篇数，并在同一台账记实际产量与缺口，不降低质量凑10篇。
