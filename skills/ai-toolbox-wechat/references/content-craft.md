# 内容方法与辅助能力

只在当前文章确有缺口时调用辅助 Skill。总入口负责成稿与审稿，选题、视觉和草稿交付仍走现有三个专项；不增设台账、图床、模型密钥或发表入口。

## 按缺口选择

| 本次缺口 | 使用方式 | 完成的依据 |
|---|---|---|
| 中文空话、重复、模板腔 | 按需读取 `humanizer-zh`；一般中文终审优先它，其他文体可用已有 `humanizer`，不默认串两轮 | 改写清楚且原有主张、限定与可复制成果均保留 |
| 正文缺少解释某个概念的图 | 视觉专项按需读取 `baoyu-article-illustrator`，选图位、类型、风格和配色 | 图回答一个明确问题，与正文位置和图注相符；真实操作仍由截图证明 |
| 原创封面缺少构图与视觉识别 | 视觉专项按需读取 `baoyu-cover-image`，结合主题、构图、配色、画法、标题文字与情绪 | 图与文章任务一致，标题与文章同文，横图和方图均检查核心词、主体、对比和缩略可读性 |
| 操作过程、真实结果、软件入口 | 使用实际截图或有来源的官方演示 | 图片具有对应操作或官方来源证据，不拿生成插画冒充界面 |
| 流程、数据、对比、结构关系 | 使用现有图表能力与可编辑源文件 | 文字、数字、关系与本篇证据一致 |
| 微信正文样式或文章二次复用 | 使用现有排版/设计能力；确有 PPT、网页、卡片交付要求时再加载相应 Skill | 目标平台确实打开和检查；HTML、PPT 或本地封面不能冒充微信已更新 |

辅助目录按宿主技能清单定位，缺少本地目录不阻止 Muse 完成可用步骤。公开阅读入口包含下面的账号适配规则；只有需要某种具体风格或完整编辑细则时才读相应上游资料，不让每篇文章加载整包。

## 中文终审的事实保护

只修改有具体问题的句子。检查顺序是信息和确定程度、段落逻辑、术语与示例一致，最后才是语气；不是给文章强塞第一人称、情绪、金句或所谓爆款结构。

润色前后对照数字、日期、版本、比较对象、归因、否定、条件和完成状态。例如“仅在同一网络可用”不能变成“随时可用”，“计划支持”不能变成“已经支持”，“可能减少操作”不能变成“效率翻倍”。作者没有提供的亲历、用户反馈、测试时间和性能数字不能补造。不要把“尚未查证”改成“官方从未公布”。

保留标题层级、代码块、命令、URL、图片地址及用途对应关系。已通顺的文本可以不改；研究缺口交回选题环节，不能靠改写掩盖。改稿后重新审查本版的事实、可带走成果、示例操作与费用/权限条件，再运行现有预检并记录新正文指纹；旧远端核验不能继承给新文字。

## 图位和封面的用法

先决定“这里需要看见什么”：步骤、成果、关系或隐喻，再选择素材；没有解释价值的插画可以省略。每张图只承担一个主要概念，复杂流程拆图，关键提示词与步骤留在正文供复制。不机械规定每篇几图、每次出几版。

原创插画先保存提示词，注明对应正文位置、来源支持的要点、图中文字、风格、比例和要避免的误读。技术图中的标签与数字优先使用可验证的图表工具；一旦选用位图生图，就交当前宿主原生 `image_gen` / `imagegen`，不拿代码绘图假称已调用生图。文字有误或不清楚时按宿主图像编辑流程修订并复查，不用局部贴字遮盖缺陷来冒充正确输出。

默认沿用本号视觉标准中的明亮蓝绿与深色文字，用户本次参考与已保存偏好优先。封面主标题与文章标题同文，按实际字宽换行，不另起短标题；完整规则见编辑标准与图与封面制作。先检查 2.35:1 横图和中心方形裁切；若方形丢掉主体或关键词，调整构图，确需精简则同步修改文章与封面标题。确有真实可用的封面上传能力时才能交付到后台；当前草稿接口无 `cover` / `theme`，本地封面仍交由本人更换。

在没有原生出图能力的 Muse 环境，交付图位、提示词和能力缺口即可，不声称已生成或上传。不能安装 `baoyu-image-gen`、Bun、CLI wrapper，不能借辅助 Skill 搜索密钥、切换付费 API、读取其他工程配置、自动登录或上传私有资料。上游首次配置、`EXTEND.md` 或确认习惯不改变当前用户授权；普通可恢复的风格选择用已有偏好，不新增强制审批。保留原件和修改版本，涉及删除整个文件时遵守系统废纸篓规则。
